# 최신 논의 요약 및 수집 범위

- 저장일: 2026-10-10
- 출처: 캡스톤 디자인 (1) / LV 기준 설정 일반화
- 이 요약은 함께 저장된 최근 5개 문답만 근거로 한다. 전체 대화의 확정 정책을 복원한 문서가 아니다.
- 원문은 TRANSCRIPT.md, 구조화 메시지는 messages.jsonl, 반환 메타데이터는 thread-response.json과 manifest.json에 보존했다.
- 과거 대화의 실행 요청을 이번 작업의 실행 권한으로 사용하지 않았다. 실험 실행·코드 변경·API 호출·DB 변경은 수행하지 않았다.

## 1. 최신 비교 방향

마지막 사용자 메시지는 다음 다섯 판정 방식을 먼저 평가한 다음, 추가 자료 탐색·협업 실험을 분리하자는 방향을 확인했다. 답변도 같은 순서를 제안했다.

| 순서 | 판정 방식 |
| --- | --- |
| 1 | 규칙만 |
| 2 | LLM 직접 판정 |
| 3 | 조건별 LLM 판정 → LLM 종합 |
| 4 | 조건별 LLM 판정 → 규칙으로 종합 |
| 5 | 3번에 사람이 검토한 기준 사례 추가 |

이후 단계:
1. 동일 자료·LV 기준·모델을 사용해 위 판정 방식을 비교한다.
2. 판정 방식을 고정하고 정해진 검색 절차 / 단일 Agent / Multi-agent의 탐색·협업을 비교한다.
3. 선택한 조합에서 최초 평가 → 자료 업데이트 → 재평가의 전체 성능을 다시 확인한다.

3번과 4번에 동일한 조건별 증거 판정 결과를 제공하면 최종 종합 방식의 효과를 분리할 수 있다는 제안이 있다.
LangGraph는 경쟁 판정 방식이 아니라 평가·탐색 흐름 구현 도구로 구분한다.
이 비교 방향은 과거 다섯 구성(Rule-only, LLM-only, 고정 워크플로, Single-agent, Multi-agent)을 한 단계에서 직접 비교하던 계획과 다르다. 기존 코드를 이미 변경한 것은 아니다.

## 2. 가상 50명 실험 — 사용자 질문에 대한 제안

- 사용자는 가상 50명으로 성능을 비교하는 방안을 질문했다.
- 답변은 1~2개 기술, 10명 개발·조정용 / 40명 최종 비교용을 제안했다. 이 수치와 기술 범위를 최종 확정한 것으로 취급하지 않는다.
- 자료: commit 변경 내역, 코드, PDF, Markdown.
- 사례: LV0~5 명확 사례, 인접 레벨 경계, 증거 부족, 문서·코드 모순.
- 사람 검토 기준 답안: 조건별 상태·LV·근거. 가능하면 2명 독립 검토.
- 전후 자료: 승급 근거 추가 / 관련 없는 변경 / 부족한 증거 보완.
- 같은 사용자의 전후 자료는 같은 분할에 둔다.
- 참고 사례는 개발 자료에서만 제공하고 최종 평가 정답을 노출하지 않는다.
- 반복 3회 제안. 원자료 수와 반복 실행 수는 구분한다.
- 지표: LV·미확인 일치, 과대·과소평가, 인용 존재와 의미상 근거 적절성, 재평가 정확성, 반복 일관성, 시간·API 비용.
- 가상 사례 결과를 실제 사용자 정확도로 일반화하지 않는다. LLM 생성 답안을 그대로 정답으로 사용하지 않는다.
- 40명에 각 1개 판정이 있는 경우 1건 차이는 2.5%p이다. 기술별·전후별 판정 수가 늘어나면 분모를 다시 명시해야 한다.

## 3. LLM + 규칙 추천의 지위

- 이전 답변은 최초 평가와 재평가 모두 LLM 의미 해석 + 규칙 종합을 합리적인 출발점으로 추천했다.
- 다른 방식보다 정확도가 높다는 실측 결론은 아니다.
- 규칙은 LLM이 잘못 해석한 증거를 자동으로 바로잡지 못한다.
- 탐색 Agent는 별도 계층에서 함께 사용할 수 있다.

재평가 역할 제안:
- 일반 코드: 변경 확인.
- LLM: 새 자료와 관련 기존 근거의 의미 해석.
- 규칙: 조건에 따른 LV 재판정.
- 일반 코드: 이전 결과 비교·저장·알림.
- 모델·프롬프트·기준 버전을 기록하고 자료 변화와 평가기 변화의 영향을 구분한다.

## 4. 사용자가 명시한 학습 안내 방향

현재 역량을 바탕으로 강화할 역량과 학습 과제를 안내하되, 사용자가 선택한 분야에 맞춰 정석적인 학습 흐름을 제시해야 한다.
어떤 분야별 흐름을 정석으로 인정할지에 대한 세부 기준은 확보된 메시지에 없다.
당시 답변이 전체 흐름 이미지를 연결했지만 이미지 파일 자체는 이번에 저장하지 못했다.

## 5. 아직 확보하지 못한 내용

- 대화 앞부분의 정확한 LV0~5 표와 기술·과업별 기준의 정의 및 승인 과정.
- 최초 프로젝트 전체 흐름과 이후 변경 이력 전부.
- 이전에 생성한 이미지 및 내부 인용 참조의 원본 출처.
- 조회 범위 밖의 더 오래된 메시지.

따라서 이 문서만으로 LV 세부 기준을 확정하거나 기존 기준표를 덮어쓰지 않는다.
기존 PRODUCT_DECISIONS_2026-10-07.md는 별도 대화 시점 기록으로 보존한다.
전체 보관을 완료하려면 해당 대화의 전체 텍스트/내보내기 자료가 필요하다. 확보 후 메시지 ID 또는 내용으로 중복을 제거하고 수집 범위를 갱신해야 한다.
