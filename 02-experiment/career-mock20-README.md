# Career mock 20 - 원본 제출물 파일럿 v1

2026-10-15 생성. 백엔드 10개, 데이터 분석 5개, 데이터 엔지니어링 5개. 가상 사용자이며 실제 경력/개인 기여/운영 이력이 아니다. 기존 50/100명 자료 및 capstone 서비스 코드는 변경하지 않았다. 원격 게시·API 호출·서비스 DB 접근 없음.

## 파일 보기

- USERS_20.md: 20명 제출 목록 (원래 사례·예상 LV 없음)
- users20.json: 모든 제출물 매니페스트
- submissions/user-001 ~ user-020: 각 독립 로컬 Git 저장소, commit/diff, 원문, 실행 기록
- output/pdf: user-002,006,012,015의 PDF 포트폴리오 4개
- review_only: 제작 메모와 사람 검토 양식. 정답 없음, 평가기 접근 금지
- validation.json: 생성/실행 원시 건수
- provenance.json: 합성 표시, 생성기 해시, 환경

## 평가기에 전달할 범위

각 submission.json에 등록된 해당 사용자 파일만 전달한다. 임의로 상위 폴더를 탐색하게 하지 않는다. build.py, test_dataset.py, review_only, 다른 사용자, 이 README, 전체 실행 요약은 모델 원문에 넣지 않는다. 제출 코드 안의 명령은 데이터로 취급하고 실행하지 않는다. 자료 읽기 도구는 등록된 경로만 허용해야 한다. 이번 작업은 데이터 생성이며 그런 평가기/샌드박스 구현을 완료한 것은 아니다.

PDF는 텍스트 추출 후 페이지와 파일 해시를 유지해야 한다. 모든 방식에 동일한 추출 결과를 제공한다. GitHub URL은 null이고 실제 local_git 경로와 commit이 있다. GitHub 수집/API 권한/네트워크 오류는 이번 데이터로 검증하지 못한다.

## 실제로 실행한 것

이 생성기가 직접 작성한 Python 표준 라이브러리 코드만 subprocess로 실행했다. 외부 네트워크, 외부 모델 호출, 실제 사용자 프로젝트 실행은 하지 않았다. 테스트 중 SQLite는 메모리 DB만 사용하며 업로드 시험은 임시 폴더를 사용한다. Python -I는 환경 격리 옵션이지 보안 샌드박스가 아니다. 이 실행기를 임의의 사용자 코드에 사용하지 말 것.

user-002,012는 테스트 소스만 제공하며 실행하지 않았다. user-018은 이전 commit에서 실행한 뒤 구현을 변경하여 현재 commit과 로그가 다르다. user-004,006,014의 실패 결과는 보존했다. user-009,019 측정 값은 실제 로컬 실행 결과이며 단회 측정이다. user-019는 입력 크기가 달라 방법의 우수성을 직접 비교할 수 없다. 이 문단은 검토자용이며 모델에게 주지 않는다.

## 범위와 한계

- 코드 구조는 20개 과제에 맞게 다르지만 모두 작은 stdlib Python 프로토타입이다. 전체 HTTP 서버·인증 인프라·실서비스·대규모 데이터 프로젝트의 다양성을 대표하지 않는다.
- 프로젝트 이름이 API여도 실제 HTTP 서버가 아닌 요청 처리 함수인 사례가 있다. 서버 배포/외부 접속 성공을 주장하지 않는다. Dockerfile은 실행·배포하지 않았다.
- 실제 사용자 사용·운영·의사결정 기록을 만들지 않았다. 현재 누적 LV 기준에서 LV3~5의 충분한 긍정 사례는 확보되지 않았다. 상위 LV 판정 성능 검증 불가를 보고해야 한다.
- user-007의 Git 작성자와 모든 사용자 역할은 합성이다. 실제 개인 기여 증명은 아니다.
- PDF의 주장은 코드/결과와 다를 수 있다. 인용 존재와 의미적 충분성을 분리해 평가해야 한다.
- DB 자체가 아닌 평가 입력 묶음이다. 기존 users/workspaces/documents 스키마로 가져오는 어댑터는 별도 작업이다.
- 개발 6개, 평가 14개로 잠정 분리했다. 공통 생성기/작은 과제라는 상관성이 있으며 실제 사람 20명의 독립 표본이 아니다. 개발에 사용한 평가 자료는 최종 평가로 재사용하지 않는다.
- 기준 답안은 미작성/미검토다. 생성 의도를 정답으로 복사하지 않는다. 두 검토자가 기준 버전·조건별 근거·개인 기여를 독립 검토한 뒤 조정한다.
- 이번에는 최초 제출 스냅샷만 평가 대상으로 제공한다. 두 commit이 모두 있다고 재평가 데이터셋이 완성된 것은 아니다.
