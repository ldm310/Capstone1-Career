## 지금 결정 (사용자)

- 초기 LV 기준(LLM 4개로 공고 줄마다 정한 요구 LV)은 폐지했다(2026-11-14).
- 2026-11-24 사용자가 변수 설정(위 1·2번 문서)을 정하고 개발 시작을 지시했다.
  - 카테고리 7개: 프로그래밍 활용(언어마다)·운영 배포·백엔드 개발·데이터 엔지니어·데이터베이스·프론트엔드 앱·AI 기술
  - 계산: 개수 변수 → 단계(0~5) → 단계 평균(소수 첫째 자리). T/F 변수와 개수 변수(부가 기술 수 등)는 가점이다(점수 크기·방식은 미정, 아래 '미정' 참고). 백엔드만 점수형(6변수 평균)이다.
  - 단계 시작값·가점 0.5·유통기한 1달·백엔드 항목 점수는 임시값이고, 8명 테스트로 맞춘다.
  - 문서에 없는 단계 시작값은 Claude가 임시값을 먼저 잡고, 8명 레포에서 잰 값을 보고 임계치를 정해 사용자에게 보여 준다(2026-11-25 사용자 결정). 그 숫자에는 「Claude 임시값」 표시와 근거(8명의 값)를 붙인다. 그 밖에 문서에 없는 숫자는 지어내지 않고 묻는다. 단계 시작값은 2026-11-26에 사용자가 고정 사다리로 확정했다(아래 '임계치').
- 분석 범위: 레포마다 기본 브랜치(main)·develop·dev의 본인 줄만 본다.
- 레포 범위(2026-11-26 사용자 결정): 본인 소유 레포만 보지 않는다. 본인이 커밋한 모든 공개 레포(팀·조직·남의 레포 포함)를 본다. 백엔드 레포가 없다는 이유만으로 백엔드 LV를 0으로 두지 않는다. 2단계는 본인 소유·포크 아닌 레포만 봤다.
  - 큰 레포(2026-11-26 사용자 결정): 레포 전체 크기가 400MB(「Claude 임시값」, 2단계 스크립트 값)를 넘으면 빼지 않고, 필요한 파일만 받는 방식(blob:none)으로 받은 뒤 내 커밋이 바꾼 파일만 받는다. 2단계 실측으로 가장 큰 레포(3.4GB)도 63초·309MB였다. 해당은 남의 큰 오픈소스 레포 5개이고, 그 안의 내 커밋은 14개다.
- 쏠림 표시(2026-11-26 사용자 결정): 연습 레포 규칙을 적용한 뒤에도 4단계 이상(「Claude 임시값」)이고, 그 값의 80% 이상이 레포 하나에서 나온 칸만 사람이 확인할 목록에 올린다. 자동으로 빼지는 않는다. 2단계 값으로는 16칸이고, P17 dbt 결과 폴더·P18 라이브러리 폴더 같은 부풀림을 모두 잡는다. 그 두 경로는 표시와 별개로 생성·외부 파일 거름 목록에 넣는다.
- PocketBase 팀 레포(2026-11-26 사용자 결정): 누구의 LV도 재지 않고, 규칙이 PocketBase 호출을 다 잡는지 시험하는 용도로만 쓴다. 보내는 요청 기준 12종을 모두 잡으면 통과다(2단계 규칙은 0/12).
- 8명 테스트: 8명이 각자 커밋한 공개 레포 주소(팀 레포 포함)만 받는다. 비공개 레포는 받지 않는다(2026-11-25). 2026-11-26 사용자 결정: 2단계 12명(P01~P12)으로 테스트를 대신하고, 레포를 따로 받지 않는다. 이 문서에서 '8명'은 이 12명을 뜻한다. 남은 후보 3명(프론트 중·중하, AI 하)은 돌리지 않는다.
- 프론트엔드 앱(2026-11-26 사용자 결정): 모바일 앱 코드에서 프론트 개발을 했으면 넣는다. BaaS(Supabase 등) 호출도 API 연동 수로 센다.
  - 앱의 백엔드 역할을 하는 BaaS는 테이블+동작 단위로 센다. 지도·결제·푸시 같은 다른 외부 SDK는 서비스당 1로 센다. 분석·오류 수집 도구와 reCAPTCHA는 외부 SDK로 세지 않는다(2026-11-26). 결과에 "그중 BaaS n개"를 표시한다.
  - 세는 단위(2026-11-26 사용자 결정): 외부 REST 서비스(fetch·axios로 남의 서버 API를 직접 부름)는 내 서버 API처럼 경로마다 세고, 결과에 "그중 외부 REST n개"를 표시한다. 외부 SDK '서비스당 1'은 프로젝트(사본 묶음)마다 센다. BaaS 동작은 보내는 요청(메서드+경로 틀)마다 센다. BaaS마다 SDK 메서드 → 요청 대응표를 정의 파일에 둔다.
  - 규칙·LLM 질문 틀·정의 기록이 2단계에서 서로 달랐다(질문 틀은 "SDK는 세지 말라"). 정의는 한 파일에만 두고 규칙과 질문 틀이 그 파일을 읽는다. 실행 기록(run_log)에 어느 정의 버전으로 돌렸는지 남긴다.
  - BaaS를 쓴 사람의 API 연동 값은 정의를 맞춘 뒤 다시 계산한다(11/19 계획의 PocketBase 팀 레포도 사례로 본다).
- 연습·강의 레포(2026-11-26 사용자 결정): 가져오기만 하고 스스로 한 흔적이 없으면 역량을 재지 않는다. 스스로 한 흔적이 있는 부분만 넣는다. 세부(2026-11-26 사용자 결정, Claude 추천안을 고름):
  - 통째 올림(R2)은 연습·강의 레포와 사본에만 적용한다.
  - 수업 시간에 따라 친 코드는 모두 뺀다.
  - 부트캠프 사본은 공개 원본이 있으면 원본의 내 커밋으로 세고, 없으면 뺀다.
  - 본인이 만든 강의 자료는 LLM이 '본인 자료'로 보면 보통 레포로 본다(같은 내용 파일 한 번 규칙만 씀).
  - 알고리즘 문제 풀이는 커밋 수에서만 빼고, 줄·기간에는 넣는다.
  - 원칙(2026-11-26 사용자 결정): 자기가 한 부분이 아니면 뺀다. 대회 노트북은 대회가 준 파일(베이스라인·제출 양식·대회 소개)을 빼고, 본인이 고치거나 새로 쓴 부분만 센다. 연습 레포 숫자 기준(통째 올림 10개·300줄·30%, 수업 메시지 30%, 문제 풀이 50%, 「Claude 임시값」)은 '본인 것이 아닐 수 있는 후보'를 고르는 데만 쓴다.
  - 「제안」(확인 전): 베이스라인을 닮았지만 이름이 다른 파일처럼 애매한 것은 LLM이 가린다. 본인 것이 아닌 파일만 만든 커밋은 커밋 수·기간에서도 뺀다.
- 임계치(단계 시작값, 2026-11-26 사용자 확정): 사람 값과 무관한 고정 사다리다(Claude가 낸 ① 고정 사다리에서 기간 4개와 DAG를 사용자가 고침). 커밋 1/7/30/180/365 · 바꾼 줄 1/200/1,000/5,000/25,000 · 기간(프로그래밍, 일) 1/7/30/150/300 · 배포 레포 1/2/3/5/8 · 배포 기간(일) 1/7/50/150/250 · DAG 1/2/5/10/20 · 데이터 엔지니어 기간(일) 1/7/30/100/250 · 설계 테이블 1/3/8/20/50 · DB 기간(일) 1/7/30/120/250 · API 연동 1/3/10/30/100 · 데이터 송수신 1/3/10/30/100 · 이벤트 처리 1/10/30/100/300. AI 기술은 문서 값 그대로다. 명세 예시(커밋 120·줄 8,000·90일)는 3/4/3 = 3.3이다.
- API 키(2026-11-26 사용자 결정): 프로그램이 보관 폴더의 키 파일에서 읽는 지금 방식을 유지한다. Claude는 그 파일을 열거나 출력하지 않는다.
- LLM 비용: 한도를 따로 두지 않고 잔액까지 쓴다(2026-11-25 사용자 결정). 부르기 전에 예상 금액을 알리는 것은 그대로 한다.
- 운영 배포 기간: 명세의 Actions 방식(레포별 Actions 첫 실행일 ~ 마지막 커밋일, 유통기한 없음) 그대로 간다(2026-11-25). 공개 레포의 Actions 실행 기록은 90일이 지나면 지워지므로, 첫 실행일은 워크플로 파일이 처음 들어간 커밋 날짜로 잰다(Claude 제안, 측정 방법). 마지막 커밋일은 내 마지막 커밋이다(2026-11-25 사용자 결정: 운영 배포와 Actions는 본인이 해야 하므로). 제안(확인 전): 배포 파일(워크플로·배포 스크립트)을 내가 쓴 레포만 '배포한 레포'로 세고, 워크플로가 내 마지막 커밋보다 늦게 들어왔으면 0일로 본다.
- 목표: 공고마다, 공고 요건 문장마다 그 사람의 역량 점수를 낸다. 사람마다 한 번 낸 카테고리 LV·기술 기록에 공고용 가점을 더한다(흐름 2026-11-25 사용자 확인).
- 변수 뽑기(2026-11-25 사용자 결정): ① 코드와 기록은 도구(clone, GitHub에만 있는 정보는 API)로 받는다. ② 도구로 못 가져온 부분만 LLM이 맡는다(LLM이 도구를 골라 다시 가져온다). ③ 받은 코드 전체를 규칙으로 변수에 맞춰 LV를 잰다. ④ 못 뽑힌 것(받기·분석 실패), 안 뽑힌 것(근거를 못 찾음), 애매한 것은 처음으로 돌아가 도구 + LLM으로 다시 파악하는 일을 최대 3번까지 한다. ⑤ 그래도 안 되면 로그 파일에 남기고 LV에서는 모름으로 뺀다. LLM은 Claude Haiku 5.5(`claude-haiku-5-5`)를 쓴다(2026-11-27 사용자 결정: API 크레딧을 아끼려고 바꿈. 11-25에는 Sonnet 5.5였다). Claude Code에서 개발할 때(대화·서브에이전트·워크플로)는 이와 별개로 Opus 5.5 max·울트라코드를 쓰고 토큰을 아끼지 않는다(2026-11-27 사용자 결정). '안 뽑힌 것'은 흔적(의존성·설정·규칙 없는 스택 코드)이 있는데 못 뽑은 경우만 다시 본다. 흔적이 전혀 없는 0은 LLM에 보내지 않고 '안 씀'으로 둔다(2026-11-26 사용자 결정. 2단계 표본 66건 중 '예'는 간접 1건이었다).
- 코드 구조 분석: tree-sitter를 계속 쓴다(2026-11-26 사용자 결정. 2단계 스파이크는 설치 없이 정규식으로 읽었다). Python은 표준 ast, Java·Kotlin·JS·TS(TSX)·Swift는 tree-sitter로 읽는다. 정한 언어에서는 정규식으로 대체하지 않고, 파서가 없으면 멈춘다. 결과에 쓴 파서를 남긴다. 판·해시는 [requirements.lock](requirements.lock)에 있다(코어 0.26.1). `lv-stat/.venv`(Python 3.12, git 제외)에 `--require-hashes --only-binary=:all: --no-deps`로 설치했다(2026-11-26). CI 잡에도 같은 설치 단계를 둔다.
- LLM이 뽑은 값은 처음부터 LV에 넣고, 결과에 「LLM 추출」로 표시한다(2026-11-25 사용자 결정).
- 본인 확인은 필수다: 본인 GitHub 계정의 커밋만 센다(2026-11-25 사용자 결정). 방법(Claude 제안): GitHub API로 그 계정이 쓴 커밋 목록을 받아 clone 기록과 맞춘다. noreply 이메일은 API 없이 확인한다. 계정에 연결 안 된 이메일 커밋은 빼고, 본인이 알려 준 이메일만 넣는다.
- 백엔드 [본인 확인] 항목(작성자 = 로그인 사용자): 로그인 사용자와 비교한 것만 센다(2026-11-25 사용자 결정: 로그인이 필수). 요청에 대상 번호(URL·본문·쿼리)가 없고 서버가 로그인 사용자의 것만 찾아 고치는 API(예: 내 알림 모두 읽음, 내 오늘 목록 저장)는 분자·분모 모두에서 뺀다(2026-11-25 사용자 결정). '글 비밀번호로만 막는 API'를 따로 가리는 규칙은 두지 않는다(2026-11-26 사용자 결정: 프로젝트에 필요 없음. 2단계에서 그렇게 분류된 3곳은 모두 잘못 분류였다). 「제안」(확인 전): 로그인 사용자와 비교하지 않는 수정·삭제 API는 따로 빼지 않고 '본인 확인 없음'으로 센다.
- [AI 확인] 항목(2026-11-26 사용자 결정): B안(LLM 값을 처음부터 LV에 넣음)으로 쓰면서 사람 판정 표본을 따로 모은다. 사람 판정과 90%에 못 미치는 항목만 A안(명세 규칙 13: 만점에서 뺌)으로 돌린다.
- 가점(2026-11-26 사용자 결정): 명세 방식이다. T/F는 T면 +0.5(최대 5.0). 개수 가점(부가 기술 수·검증된 AI PR 수·백엔드 부가 영역 수)은 단계로 바꿔 평균을 올릴 때만 넣는다.
- 데이터베이스 깊이(2026-11-26 사용자 결정): 명세대로 근거 1곳이면 그 단계다(2단계의 '3~5단계는 파일 2곳' 규칙은 뺀다). 근거 파일 수는 점수에 넣지 않고 기록으로만 보인다. 5단계(쿼리 튜닝)는 쿼리 튜닝 전체로 본다(2026-11-26 사용자 결정, 두 번째). N+1 해결은 그 한 종류로, 연관 데이터를 쓰는 목록 API의 절반 이상에서 N+1이 없어야 한다. 다른 튜닝(실행 계획 확인·배치 조회·페이지 나누기 최적화 등)도 근거로 인정한다. 어느 근거든 필요한 곳에 다 했는지를 LLM이 확인한다 [AI 확인]. 한 줄로 5단계가 되지 않는다. 탐지 예시는 백엔드 문서의 'DB·ORM별 탐지 예시' 표(N+1 해결 줄)를 쓴다. 연관 데이터를 쓰는 목록 API가 없으면(분모 0) '5단계 판정 대상 없음'으로 두고 4단계까지 본다. 목록 API가 1~3개뿐이어도 명세대로 비율만 보고, 결과에 분모를 표시한다(2026-11-26 사용자 결정).

## 작업 규칙

- 한국어로 핵심만 답한다. 사용자 생각이 틀리면 분명히 말한다.
- 정책·세부는 혼자 정하지 않고 묻는다. 정하지 않은 것은 「미정」, Claude 의견은 「제안」으로 적는다.
- 증거를 지어내지 않는다. 합성 데이터는 합성이라고 쓰고, 재지 않은 정확도는 N/A로 둔다.
- 받은 레포의 코드는 읽기만 하고 실행하지 않는다(빌드·설치·시험 포함).
- **공개 레포다.** 비밀값(`.env`·토큰·DB 주소·암호), 공고 글(회사·제목·링크·요건 문장), 지인 계정·레포 이름을 파일이나 commit에 넣지 않는다.
- 팀 DB는 읽기 전용으로만 접속한다.
- 유료 API(Claude 등)는 부르기 전에 비용을 알린다. 결제나 한도가 모호하면 멈춘다.
- `feature/lv-stat`에서 작업하고 PR로 develop에 합친다. 합칠 때 `.github/workflows/ci.yml`에 lv-stat 잡을 더한다(팀 규칙). commit·push는 사용자가 말할 때만 한다(예외: 위 '스테이징 LV 서비스').
- 다른 파트 폴더(`backend/`·`frontend/`·`job-skill/` 등)는 읽기만 한다(예외: 위 '스테이징 LV 서비스'에 필요한 부분).

## 폴더

- `docs/`: LV 계산 규칙(11-24), 결정 메모와 손그림
- `pipeline/`: GitHub에서 내 줄을 뽑는 코드(Python 표준 라이브러리 + git)
  - 내 줄 뽑기: `clone.sh`(받기) → `identity.py`(레포마다 내 git 이름 찾기) → `bundle.py`·`extract.py`(내 줄 → 근거 묶음, 규칙은 `lv1_rules.py`·`lv_dict.py`)
  - 점검·stat: `make_packets.py` → `verify_agent.py`(Claude Haiku 점검, 유료) → `apply_verdicts.py` → `to_stat.py`(`keys.py`의 키 이름)
  - 한 번에 돌리기: `run_profile.py`(계정 URL)는 공고 파일(`data/postings.json`)이 없으면 레포를 돌기 전에 멈춘다. `run_pipeline.py`(레포 하나)는 1단계(근거 묶음·packet)까지는 공고 파일 없이 돈다. `data/`는 가져오지 않았다.
  - 폐지된 기준에 묶인 것: `tag_postings.py`·`match.py`(줄별 요구 LV), `make_report.py`의 공고 부분
  - 측정용: `run_eval.py`·`audit45.py`·`recall45.py`·`score_verifier.py`(측정 자료 `eval/`는 가져오지 않았다)
  - 시험: `python3 pipeline/selftest.py`(합성 레포만, 네트워크 없음). 2026-11-24에 이 폴더에서 97/97 통과했다.
- `service/`: 스테이징 LV 서비스 첫 판(2026-11-27). `worker.py`(요청 파일을 하나씩 분석)·`analyze.py`(레포 찾기 → 받기 → 색인 → 규칙 → 계산)·`s2/`(2단계 규칙 코드 사본, gh 대신 `ghapi.py`)·`CONTRACT.md`(웹과 주고받는 파일 형식·문장 점수 규칙). 시험: `python3 -m unittest discover -s lv-stat/service/tests -v`. 계획: [docs/superpowers/plans/2026-11-27-staging-lv-service.md](docs/superpowers/plans/2026-11-27-staging-lv-service.md)
- `schemas/`: 결과 JSON 형식. `examples/shopmall-eun/`: 합성 레포로 낸 예시
- `requirements.lock`: tree-sitter 파서의 판·해시. `.venv/`(git 제외)에 설치한다.
- `repos/`(받은 레포), `out/`(결과), `.env`, `.venv/`, `cache/`는 git에 넣지 않는다.
