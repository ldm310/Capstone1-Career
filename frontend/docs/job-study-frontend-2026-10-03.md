# 공고별 비교·수준별 스터디 FE

기준일: 2026-10-03. 기존 통합 요구사항보다 이 문서의 최신 사용자 결정을 우선한다.

## 사용자 확정 사항

- 공고 카드의 기존 커버 영역에 자격요건 만족·불만족을 먼저 표시하고, 우대사항 만족 개수 및 해당 공고와 연결되는 기술별 사용자 LV를 표시한다.
- 기술 LV와 공고 지원자 집단의 Low / Middle / High는 다른 개념이다. 산정 기준은 모두 미정이다.
- 실제 판정은 ‘판정 대기’, 예시 데이터는 별도 체험으로 제공한다. 미확인을 불만족으로 바꾸지 않는다.
- 실제 지원 여부는 외부 채용 페이지에서 지원한 뒤 사용자가 ‘지원했어요’로 직접 확인한다. 링크 클릭으로 지원 완료 처리하지 않는다.
- 스터디는 지원 확인 후 신청한다. 같은 공고의 같은 상대 수준 스터디만 보여준다. 다른 수준의 모집을 노출한 뒤 신청을 거절하는 방식은 사용하지 않는다.
- 공고 상세 안에 스터디 탭을 제공하고, 별도 ‘내 스터디’ 메뉴에서 참여한 스터디를 모아 보여준다.
- 스터디에는 멤버·공동 로드맵·과제 진행률·채팅·일정·자료 공유를 포함한다.
- 신청자가 한 명이어도 시작할 수 있다. 최소 인원을 기다리게 하지 않는다.
- Low는 Middle을, Middle은 High를 준비하는 경로를 제공한다. **High도 개인·그룹 맞춤 로드맵을 제공한다.** High는 자율 활동만 한다는 이전 안을 대체한다.
- 필터는 정렬 / 채용구분 / 상세조건으로 구성한다. 채용구분은 신입·경력·인턴·경력 무관 복수 선택이다.
- 인기순·추천순은 제공하지 않는다. 최신순·마감일순을 표시한다.

## 이번 FE 구현 범위

| 영역 | 동작 |
| --- | --- |
| 실제 공고 `/jobs` | 기존 공식 공고 피드와 검색·저장·더보기 유지. 상단 비교는 판정 대기. 상세 페이지·스터디 탭 연결 |
| 실제 지원 기록 | 기존 게스트/계정 저장 API에 사용자 확인으로 ‘지원 완료’ 기록. 기존 지원 관리에서 확인 가능 |
| 실제 공고 필터 | 전체 피드에서 채용구분 필터·정렬. 정보가 없는 경우 임의로 경력·마감일을 만들지 않음 |
| 별도 체험 `/jobs?demo=low` | 가상 기업 3개와 명시적 예시 비교 결과. Low/Middle/High 시나리오 전환은 체험 도구이며 실제 수준 선택 기능이 아님 |
| 스터디 목록 | 예시 공고 지원 확인 후 해당 시나리오 수준의 스터디 2개만 노출. 목록·방 접근 모두 공고/수준 식별자를 확인 |
| 스터디 참여 | 예시에서 참여 신청 즉시 개인 시작 가능. 동일 방 중복 등록 방지 |
| 내 스터디 `/studies` | 실제 연결 준비 안내. `?demo=low` 등에서는 해당 예시에서 신청한 스터디 표시 |
| 방 안 활동 | 과제 체크·진행률, 나 1명 멤버 표시, 채팅 작성, 일정 추가·삭제, HTTP(S) 자료 링크 추가·삭제 |
| 기록 유지 | 예시 지원·방·활동은 전용 브라우저 localStorage에 저장. 실제 계정 기록과 분리. 새로고침 후 복원 |

## 아직 제공하지 않는 실제 기능 / 미정 정책

- 실제 사용자 자료 기반 자격 충족 판정 및 LV 계산, 지원자 집단 통계·상대 수준 계산.
- 실제 스터디 모집 데이터, 다른 사용자 자동 매칭, 서버 권한 검증 및 실시간 채팅·공유·공동 진행률.
- 실제 개인 코드·공고 분석 결과로 생성하는 로드맵. 현재 체험은 가상 공고의 기술과 예시 수준에 맞춘 고정 시나리오다.
- 일정 알림 발송, 자료 파일 업로드. 현재는 링크 공유 UI를 제공하며 파일 형식·제한은 미정으로 둔다.
- 그룹 최대 인원, 활동 시간 매칭, 승인·탈퇴·재분류 시 멤버십 정책. 인원 숫자나 시간 필터를 임의로 운영 기준으로 만들지 않았다.
- 과제 체크는 진행 기록일 뿐 검증 완료가 아니다. LV·상대 수준·포인트를 변경하지 않는다.
- 실서비스의 Low/Middle/High는 서버가 전달해야 하며 URL 값으로 사용자 등급을 정하면 안 된다. URL의 demo 값은 가상 체험에만 사용된다.
- 예시 방에는 실제 다른 멤버를 가장한 가짜 인원·자동 응답을 넣지 않는다. 메시지 전송·자료 공유는 이 브라우저에만 기록된다고 표시한다.

## 확인 방법

1. `/jobs`에서 판정 대기와 필터를 확인한다.
2. ‘예시로 체험하기’로 이동해 공고별 만족·불만족 및 관련 기술별 LV를 확인한다.
3. 공고의 ‘스터디 참여 신청’으로 이동한다.
4. 지원 완료 예시 확인란을 체크하고 ‘지원했어요’를 누른다.
5. 같은 수준 목록에서 ‘참여 신청’ 후 ‘스터디 들어가기’를 누른다.
6. 혼자서 과제 체크·채팅·일정·자료 링크를 기록한다.
7. 새로고침 및 내 스터디 목록에서 기록을 확인한다.

## 검증

- 신규 E2E: 실제/예시 분리, 공고별 기술 표시, 복수 채용구분·마감 정렬, 지원 확인 전 차단, 1명 시작, 기록 유지, 수준 간 접근 차단, High 로드맵, 실제 지원 기록 API 연결, 모바일·접근성.
- 기존 공고 목록·저장·검색·실패 재시도 흐름 회귀 검사.
- 기술 산정 기준이나 실제 다중 사용자 매칭을 검증한 테스트는 아니다.
