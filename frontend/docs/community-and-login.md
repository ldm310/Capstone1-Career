# 공지사항, 관리자, 로그인

2026-11-23 로컬 구현 및 RDS 적용. 원격 브랜치와 develop 배포는 별도다.

## 공지사항과 관리자

- `/notices`와 상단 공지사항 메뉴를 추가했다. 목록과 본문은 로그인 없이 열람한다.
- 관리자만 작성, 수정, 삭제, 상단 고정을 할 수 있다. 삭제는 논리 삭제다.
- RDS 마이그레이션: `db/migrations/07-notices-admin.sql`.
- `career_lv_member.app_role`에 MEMBER/ADMIN을 저장한다. 기본은 MEMBER이며, 클라이언트가 보낸 역할이나 이메일로 권한을 부여하지 않는다.
- `career_notice`는 namespace별 공지 본문, 작성자, 게시 시각을 저장한다. 게시할 때마다 로그인 세션과 RDS 역할을 다시 확인한다.
- 제목과 내용은 일반 텍스트로 표시한다. HTML을 실행하지 않는다. 변동 요청은 같은 출처인지 확인한다.
- 이용 안내와 이력서 양식 안내 두 건을 초기 데이터로 등록했다. 이후 관리자 화면에서 수정할 수 있다.

현재 로그인 계정과 세션은 기존 로컬 SQLite에 있다. RDS 권한은 해당 환경의 세션 사용자 ID와 연결한다.
이메일만 같다고 다른 환경의 계정에 관리자 역할을 자동 부여하지 않는다.

첫 관리자 이메일과 초기 설정 링크는 로컬 비공개 자료에만 보관한다.
관리자 초기화 도구 `node scripts/setup-community.mjs --admin <이메일>`은 신규 계정에 무작위 비밀번호 해시만 저장하고,
실제 비밀번호는 한 번 쓸 수 있는 설정 화면에서 사용자가 정한다. 기존 계정의 비밀번호는 덮어쓰지 않는다.
설정 토큰은 DB에 SHA-256 해시로만 저장하며 24시간 유효하다. 설정 URL은 로컬 비공개 파일에만 저장한다.
비밀번호를 설정하면 토큰을 소비하고 세션을 새로 만든다. 공개 데모 계정을 관리자로 올리는 것은 거부한다.

## GitHub 분석 미리보기

기존 `/api/analyze`는 실제 공개 GitHub 저장소를 읽는다. 가짜 URL의 실제 조회는 실패한다.
분석 화면의 `예시 링크 사용`은 `https://github.com/career-demo/order-service`를 입력하고 `GitHub 분석 미리보기`를 켠다.
링크 추가, 분석 시작 순서로 완료 화면을 볼 수 있다. 올바른 GitHub 저장소 형식이라면 다른 임의 링크도 미리보기에 사용할 수 있다.

미리보기는 별도 `/api/analysis-preview`를 호출하며 외부 GitHub와 LLM을 호출하지 않는다.
로그인한 회원의 workspace에 simulated=true로 저장하고 RDS의 미리보기 LV를 그 회원 ID로 별도 저장한다.
기존 확정 평가를 덮어쓰지 않으며 다른 회원의 자료를 조회하지 않는다. MEMBER 역할도 관리자 역할로 바뀌지 않는다.
카테고리와 분류 버전은 기존 데이터 그대로다. 공고별 다각형과 점 툴팁은 저장된 미리보기 LV를 사용한다.
PDF는 기존 업로드 경로를 사용한다. GitHub 미리보기 선택이 PDF 분석을 모의 실행으로 바꾸지는 않는다.
실제 분석 담당자가 API를 연결할 때 실제 분석 경로와 미리보기 경로를 독립적으로 교체할 수 있다.

## 카카오 로그인

기존 이메일 가입과 비밀번호 로그인은 구현되어 있다. 카카오 연결 경로와 버튼을 추가했다.
실제 카카오 인증은 아직 앱 설정이 없어 활성화되지 않았다. 자격정보가 없을 때 버튼은 준비 상태로 표시한다.

서버 전용 설정:

- KAKAO_REST_API_KEY
- KAKAO_CLIENT_SECRET
- KAKAO_REDIRECT_URI

로컬 리다이렉트 URI: `http://127.0.0.1:3000/api/auth/kakao/callback`.
스테이징에 반영한 뒤 사용할 URI: `https://staging.15-164-137-78.sslip.io/api/auth/kakao/callback`.
환경마다 실제 등록한 주소와 환경설정을 일치시켜야 한다. 앱의 카카오 로그인 사용 설정과 이메일 제공 동의 항목도 설정한다.
키와 시크릿은 각 서버의 비공개 환경설정에만 넣으며 커밋하지 않는다.

인가 코드와 토큰 교환은 서버에서 수행하고 액세스 토큰을 브라우저나 DB에 저장하지 않는다.
state를 10분짜리 HttpOnly 쿠키로 검증하고 콜백에서 소비한다. 취소, 잘못된 state, 토큰 오류를 별도로 처리한다.
신규 카카오 가입은 검증된 이메일이 필요하다. 기존 비밀번호 계정과 이메일이 같을 때 자동 연결하지 않는다.
특히 기존 관리자 이메일을 카카오 응답만으로 연결하거나 관리자 권한을 부여하지 않는다.
동일 이메일의 기존 계정은 현재 이메일 로그인을 이용해야 하며, 계정 연결 UI는 별도 작업이다.

공식 설정 문서: https://developers.kakao.com/docs/ko/kakaologin/prerequisite
공식 REST API 문서: https://developers.kakao.com/docs/ko/kakaologin/rest-api

## 화면 정리

긴 더미 안내와 분석 자료 개수는 공고 비교 화면에서 제거했다. 데이터의 DEMO/CONFIRMED 구분은 저장소와 API에 유지한다.
가운데 점을 이용한 나열은 쉼표 중심으로 바꿨다. 정식 분류 데이터의 원문과 분류 ID는 수정하지 않았다.
근무지, 접수, 기업 정보는 공고 내용 탭에서 접지 않고 표시한다.
