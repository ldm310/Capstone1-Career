# 분석과 공고별 역량 확인 (2026-11-21)

- 메뉴: 홈 / 채용공고 / 분석. `/analysis`에서 GitHub 공개 저장소 링크와 PDF 이력서를 추가한다.
- 링크·파일을 합쳐 1개 이상이면 분석 가능하다. 종류별 필수 제출은 없다. PDF 다중 선택, 링크 반복 추가, 제거를 지원한다.
- 파일은 PDF만, 파일당 10MB 이하. API에서도 확장자와 PDF 시그니처를 확인한다.
- 분석 버튼을 누르면 기존 공간을 열고 `/api/analyze`와 `/api/documents`를 순서대로 호출한다. 실패한 항목은 오류를 유지하고, 재시도 시 완료된 항목은 다시 보내지 않는다. 전 항목 성공 후에만 완료 화면을 표시한다.
- 완료 화면에는 개별 기술·LV·차트가 없다. ‘채용공고에서 내 역량 확인하기’가 `/jobs`로 연결된다.
- `/my-skills`는 `/jobs`, `/my-data`는 `/analysis`로 이동한다. 홈의 독립 역량 차트를 제거했다.
- 공고 목록·상세는 로그인 없이 열 수 있다. 조회 시 게스트를 만들지 않으며, 분석·저장 실행 시 기존 게스트 공간 기능을 사용한다.

## 키워드와 LV의 연결 범위

`GET /api/jobs/keywords?jobId=be:...`는 Spring의 `/api/postings/{id}/skill-categories`를 읽는다. 검토 완료된 필수·우대 문장에서 10개 기술 카테고리에 배정된 항목만 공고별 역량 목록에 표시한다. 제외·기타·검토 대기·미분류 문장은 LV 대상에 넣지 않는다.

저장된 분류 스냅샷은 `levelScoringEnabled=false`다. 따라서 이 변경은 LV 모델을 만들거나 SQL·React 점수를 새 역량 문장으로 복사하지 않는다. 실제 산정 결과가 없는 키워드는 `level=null`, ‘LV — · 산정 전’으로 표시한다. GitHub/PDF 분석 API의 기존 근거 추출 기능은 유지하며, 임베딩 키워드 LV 모델 연동은 별도 작업이다.

예시 공고는 저장된 코퍼스에서 가져온 검토 완료 문장 6개를 사용한다. 원문 SHA-256·source item ID·검토 버전을 함께 기록했고, 해당 가상 공고의 실제 요건이 아닌 화면 예시라고 표시한다. 예시에도 LV 숫자를 임의로 넣지 않는다.

## 검증

단일 자료·혼합 다중 자료, 부분 실패 재시도, PDF 제한, 공개 탐색, 이전 경로 이동, 모바일 접근성, 저장된 키워드 필터링과 기존 공고 기능을 Playwright로 확인한다. 테스트의 제출 요청은 고정 응답을 사용하며 외부 임베딩 API를 호출하지 않는다.
