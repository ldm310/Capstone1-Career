# 채용공고 상세 비교 화면 (2026-11-19)

기존 폰트·남색 포인트·밝은 배경·흰 카드 스타일을 유지하며 상세페이지를 두 탭으로 정리했다. 임베딩·새 LV 산정 기준·RDS 변경은 없다.

## 세 가지 상태

- 합격자 있음: 합격자 vs 나, 전체 지원자 vs 나를 별도 레이더로 표시한다.
- 합격자 없음: 합격자 자료 없음 안내와 지원자 vs 나만 표시한다. 합격자 차트를 0점으로 그리지 않는다.
- 지원 조건: 자격증·평균 학점·경력을 별도 카드로 표시한다. 현재 지원 정보는 예시라는 표시가 있다.

하단 카테고리 스탯과 막대·우대사항 막대 목록은 상세에서 제거했다. 원문·공고 본문·근무 조건·기업 정보는 아래 ‘공고 내용 보기’로 보존했다. 목록의 분석 링크도 새 스탯 탭으로 연결한다. 기존 `view=compare` 링크는 스탯으로 열리고, 지원 조건은 `view=conditions`로 구분한다.

로컬 예시:

- `/jobs?job=dummy%3Abackend-platform`
- `/jobs?job=dummy%3Abackend-platform&cohort=empty`
- `/jobs?job=dummy%3Abackend-platform&view=conditions`

## 가상 프로필과 집계

`mock/hiring-cohort.ts`는 서로 다른 가상 지원자 150명을 생성한다. 이 중 50명은 합격 프로필이다. 나머지 100명은 지원 프로필이다. 모든 ID·자격·경력·키워드 점수는 화면 확인용이다. 실제 계정·합격 이력·DB 레코드는 생성하지 않는다. 같은 사람의 점수는 공고나 조회 순서가 바뀌어도 동일하다. 실제 회사·직무의 합격자 통계로 해석하지 않는다.

기술 10개 카테고리는 백엔드 `/api/skill-categories`의 코드·이름과 일치한다. 앱과 프론트는 합친다. 샘플 키워드는 카테고리마다 3개이고, 저장된 문장 분류기나 확정 LV 규칙을 대체하지 않는다. 기존 화면의 키워드 LV(1~100)를 사용하고, 카테고리 축은 그 키워드들의 평균이다. 실제 내 자료를 읽을 수 있으면 기존 `useMyLevels`의 값을 사용하며, 없으면 ‘내 LV도 예시’라고 표시한다. 자격증·학점·경력은 기술 축에 넣지 않는다. 1~5단계 LV 임계값을 새로 만들지 않았다.

지원자 평균은 개별 150명의 키워드 LV에서 계산한다. 합격자 평균은 그중 50명의 값이다. 카테고리별 난수 평균을 직접 생성하지 않는다. ‘합격자 없음’ 예시는 합격 프로필을 양쪽 집단에서 제외하고 나머지 100명의 평균을 사용한다. 공고 카드의 기존 기술별 비교도 같은 가상 인원 집계로 맞췄다.

## API

`GET /api/jobs/benchmark?jobId=...&cohort=available|empty`는 `source=SYNTHETIC`, 버전, 가상 지원자·합격자 배열과 안내를 반환한다. 실사용자 통계 API와 별도인 Next.js 예시 API다. Spring의 기존 채용공고 연동은 유지한다. 실제 합격자료·사용자 평가 DB와 병합하지 않는다.

예시 상세 `/api/jobs?id=dummy:...`는 외부 수집이나 백엔드 공고 목록을 기다리지 않고 바로 조회한다. 비교 API 실패는 오류·재시도로 표시하며 예시 숫자로 실패를 숨기지 않는다.

## 검증

- API·집계·백엔드 계약 9개 통과: 50명 고유성, 전체 지원자에 포함, 공고 간 동일 프로필, 실제 평균, 기술 10개 일치, 빈 상태·입력 검증, 예시 상세의 외부 호출 생략.
- Edge 브라우저 관련 검사 11개 통과: 세 화면, 오류·재시도, 원문 보존, 목록→상세 연결, 기존 예시·공고 상세 회귀.
- 390px·320px에서 가로 넘침 없음. 스탯·지원 조건 화면 WCAG A/AA 접근성 검사 통과.
- 변경 파일 ESLint 및 프로덕션 빌드 통과.
- 로컬 화면 증거는 `frontend/work/comparison-with-passers.png`, `comparison-no-passers.png`, `comparison-conditions.png`, `comparison-mobile.png`에 저장했다. 화면 이미지는 저장소에 포함하지 않는다.
