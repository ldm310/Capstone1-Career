# 채용공고 상세 비교 화면 (2026-11-21)

## 2026-11-22 로컬 검수안 — 미배포

공고 목록·상세·자격요건은 비로그인으로 항상 열람한다. 공고 본문은 기본으로 펼치고, 아래에 ‘내 자료 기반 역량 비교’를 독립된 영역으로 둔다. 개인 조회 실패나 미로그인이 공고 본문을 가리지 않는다. 비회원에게는 개인 자료 API를 호출하지 않는다.

회원 비교는 현재 로그인한 회원의 `/api/career`·`/api/growth`와 해당 공고의 저장된 역량 키워드를 읽는다. 다른 기술의 점수를 문장형 역량의 LV으로 옮기지 않는다. 정확히 해당 키워드에 대한 확정 점수와 본인 근거가 있는 경우에만 LV을 표시한다. 그 외에는 ‘산정 전’으로 두며, 원문에서 기술명 등이 겹쳐 찾은 근거 후보는 별도로 표시한다. 근거 후보 연결률은 능력 점수나 합격 확률이 아니다.

본인 자료가 있으면 공고마다 달라지는 요구 키워드의 근거 연결 현황을 시각화하고, 각 항목에서 본인 GitHub·PDF 원문을 확인한다. 가상 내 프로필·가상 학점·가상 LV을 실제 회원 결과에 대신 표시하지 않는다. 회원 개인 정보가 없는 상태에서는 그래프를 임의 생성하지 않는다.

검수 HTML은 `frontend/work/job-access-review.html`이며 검수용 가상 회원 자료로 상태별 화면을 촬영했다. 사용자 승인 전에는 FE·BE 브랜치 반영·develop 배포를 진행하지 않는다.

아래는 이전 배포 구현 기록이다.

기존 폰트·남색 포인트·밝은 배경·흰 카드 스타일을 유지하며 상세페이지를 두 탭으로 정리했다. 임베딩·새 LV 산정 기준·RDS 변경은 없다.

## 세 가지 상태

- 합격자 있음: 합격자 vs 나, 전체 지원자 vs 나를 별도 레이더로 표시한다.
- 합격자 없음: 합격자 자료 없음 안내와 지원자 vs 나만 표시한다. 합격자 차트를 0점으로 그리지 않는다.
- 비교 자료가 전혀 없음: 지원 조건 탭을 자동 선택하고, 필수 조건 충족도(100점 만점)를 표시한다. 평가 자료가 없거나 확인 전 항목이 있으면 ‘산정 전’으로 남긴다. 자격증·평균 학점·경력은 점수와 별도이며, 예시 공고에서만 가상 지원 정보를 표시한다.

상태 선택 버튼은 없다. 합격자·지원자 배열 길이로 화면을 결정한다. URL의 `cohort` 값으로 상태를 바꿀 수 없다. 두 레이더는 참고 이미지처럼 위아래로 배치한다.

하단 카테고리 스탯과 막대·우대사항 막대 목록은 상세에서 제거했다. 원문·공고 본문·근무 조건·기업 정보는 아래 ‘공고 내용 보기’로 보존했다. 목록의 분석 링크도 새 스탯 탭으로 연결한다. 기존 `view=compare` 링크는 스탯으로 열리고, 지원 조건은 `view=conditions`로 구분한다.

로컬 예시:

- `/jobs?job=dummy%3Abackend-platform`
- `/jobs?job=dummy%3Adata-engineer`
- `/jobs?job=dummy%3Aserver-intern`

지원 자격 점수 예시는 필수 4개 중 3개 충족으로 75점이다. 계산은 `충족 필수 조건 수 / 전체 필수 조건 수 × 100`이며 같은 비중을 사용한다. 합격 확률·기술 LV 산정 모델이 아니다. 실제 사용자 평가 결과 연결 전에는 실제 공고에 이 예시 점수·학점·자격증을 주입하지 않는다.

## 가상 프로필과 집계

`mock/hiring-cohort.ts`는 서로 다른 가상 지원자 150명을 생성한다. 이 중 50명은 합격 프로필이다. 나머지 100명은 지원 프로필이다. 모든 ID·자격·경력·키워드 점수는 화면 확인용이다. 실제 계정·합격 이력·DB 레코드는 생성하지 않는다. 같은 사람의 점수는 공고나 조회 순서가 바뀌어도 동일하다. 실제 회사·직무의 합격자 통계로 해석하지 않는다.

기술 10개 카테고리는 백엔드 `/api/skill-categories`의 코드·이름과 일치한다. 앱과 프론트는 합친다. 샘플 키워드는 카테고리마다 3개이고, 저장된 문장 분류기나 확정 LV 규칙을 대체하지 않는다. 기존 화면의 키워드 LV(1~100)를 사용하고, 카테고리 축은 그 키워드들의 평균이다. 실제 내 자료를 읽을 수 있으면 기존 `useMyLevels`의 값을 사용하며, 없으면 ‘내 LV도 예시’라고 표시한다. 자격증·학점·경력은 기술 축에 넣지 않는다. 1~5단계 LV 임계값을 새로 만들지 않았다.

지원자 평균은 개별 150명의 키워드 LV에서 계산한다. 합격자 평균은 그중 50명의 값이다. 카테고리별 난수 평균을 직접 생성하지 않는다. ‘합격자 없음’ 예시는 합격 프로필을 양쪽 집단에서 제외하고 나머지 100명의 평균을 사용한다. 공고 카드의 기존 기술별 비교도 같은 가상 인원 집계로 맞췄다.

## API

`GET /api/jobs/benchmark?jobId=...`는 알려진 가상 공고에만 `source=SYNTHETIC`, 가상 지원자·합격자 배열, 필수 조건 평가 예시와 안내를 반환한다. 실제 공고에는 `source=UNAVAILABLE`과 빈 배열을 반환한다. 실제 합격자료·사용자 평가 DB는 아직 이 API에 연결되지 않았다. Spring의 기존 채용공고 연동은 유지한다.

예시 상세 `/api/jobs?id=dummy:...`는 외부 수집이나 백엔드 공고 목록을 기다리지 않고 바로 조회한다. 비교 API 실패는 오류·재시도로 표시하며 예시 숫자로 실패를 숨기지 않는다.
