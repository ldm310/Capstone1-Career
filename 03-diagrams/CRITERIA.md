# 다이어그램 판정 기준 (모든 라운드 동일)

판정자는 아래 항목으로만 거절할 수 있다. 각 항목은 통과/거절로 본다.
거절할 때는 **차단 문제**로 적는다. 어느 상자·화살표·문장인지, 왜 문제인지, 어떻게 고치는지를 구체적으로 쓴다.
취향이나 더 좋아질 수 있는 점은 **사소한 제안**으로 따로 적는다. 사소한 제안은 통과를 막지 않는다.

## 판정자 1 — 프로젝트 적합성 (사실 · 결정 일치)

- **F1 확정 결정과 일치**
  - 이 그림에 해당하는 FACTS.md 2장의 결정과 모순이 없어야 한다.
  - 해당 결정: LV0~5 누적형·31개 조건·4가지 상태, C안(LLM 해석 + 규칙 판정, 위험 항목만 추가 LLM, 미해결 보류, 회귀 테스트), 증거 도구 4개, 미확인 ≠ LV0, 수치는 규칙·LLM은 문장만, 스터디 매칭 제외
- **F2 미정 표시**
  - FACTS.md 3장의 제안·미정 항목을 확정처럼 그리지 않는다. 그림 안에서 '예시'·'제안'·'미정'이 보여야 한다.
  - 반대로 확정된 것을 미정으로 흐리게 그리지 않는다.
- **F3 현재 상태와 모순 없음**
  - 구현되지 않은 기능을 구현된 것처럼 그리지 않는다.
  - 레포에 실제로 있는 구현(Next.js 앱·SQLite·현재 수집기)을 '미정'으로 지우지 않는다.
  - 레포 밖 합성 실험(정확도 N/A)을 서비스 성능처럼 그리지 않는다.
- **F4 범위**
  - 직무는 데이터·백엔드다. AI는 '추후 확장'으로만 쓴다.
  - v2 범위 밖 기능(스터디 매칭·포인트·랭킹)을 흐름에 넣지 않는다.
- **F5 수치 일관성**
  - 그림 안의 계산이 맞아야 한다.
  - FACTS.md 4장의 공통 예시 값과 같아야 한다(0.75 / 0.88, 80·60·20% 등).
- **F6 기준표 일치**
  - RUBRIC_SOURCE.md의 LV 이름·조건 ID 범위·직무 예시·'인정하기 어려운 경우'와 모순이 없어야 한다.
- **F7 그림 역할**
  - FACTS.md 0장 표에서 이 그림이 맡은 주제를 빠짐없이 다룬다.
  - 다른 그림 참조('그림 N'), 단계 번호(01~04, A, B), 머리말 배지('그림 N / 9')와 섹션 태그가 맞아야 한다.

## 판정자 2 — 발표 적합성 (교수님 요구 · 가독성)

- **P1 핵심 메시지:** 제목과 부제만 읽어도 그림의 요점이 보여야 한다. 한 그림에 한 메시지만 담는다.
- **P2 설계 고민**
  - '설계 고민' 상자에 왜 이렇게 했는지가 구체적으로 있어야 한다(대안 대비 이유, 근거 수치·규칙).
  - 단순히 LLM에 던지지 않았다는 점이 드러나야 한다.
- **P3 흐름 가독성**
  - 처음 보는 사람(교수님·다른 팀)이 화살표를 따라 읽을 수 있어야 한다.
  - 화살표 종류가 범례와 맞고, 분기에는 조건 라벨이 있어야 한다.
  - 불필요한 교차·역주행이 없어야 한다.
- **P4 렌더링 품질 (차단)** 아래 중 하나라도 있으면 거절한다.
  - 글자 겹침·잘림, 상자 밖으로 넘친 글자
  - 화살표가 상자를 관통하거나 라벨이 상자를 가림
  - 슬라이드에서 읽기 어려운 작은 글씨(CSS 12px 미만)
  - 읽기를 해칠 만큼 심한 빈 공간이나 과밀
  - render 보고서의 problems가 0이 아니면서 이유가 설명되지 않음
- **P5 세트 일관성**
  - 원본과 같은 스타일이어야 한다(머리말 배지·섹션 태그·카드와 태그 색·설계 고민 상자·범례).
  - 용어를 통일한다(미확인, 기술별 LV, 내 STAT, 공고 적합도, 직무 기준표).
- **P6 발표 요구 중 이 그림의 몫**
  - 세트 전체로 서비스 전체 구조·설계 고민·현재 구현 상황·최종 목표가 보여야 한다. 이 그림은 맡은 몫을 담는다.
  - 예: 그림 1은 전체 구조와 최종 목표를 보여준다. 그림 9는 구성요소별 현재 구현 상태(구현됨 / 실험 / 계획 / 미정)를 보여준다.

## 판정 방법

- **통과 조건:** 두 판정자 모두 차단 문제가 0이어야 그림이 통과한다.
- **새 차단 문제 제한:** 이전 라운드에 지적하지 않은 새 차단 문제는 두 경우에만 낸다. 이번 수정으로 새로 생긴 결함이거나, 이전에 놓친 명백한 사실 오류(F1~F7)일 때다. 수렴을 위해 취향 변경으로는 거절하지 않는다.
- **판정 방법:** 렌더링된 PNG를 직접 본다(Read 도구). 작은 부분은 `sips -c <높이> <너비> --cropOffset <y> <x> <복사본.png>`으로 잘라 확대해서 확인한다. 원본은 고치지 말고 복사본을 자른다.
- **세트 차원 문제:** 특정 그림에 배정해서 적는다(어느 그림을 고치면 해결되는지).
