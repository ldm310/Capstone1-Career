# API 및 합격자료 현황 — 2026-11-09

확인 범위는 로컬 `http://localhost:8080`과 연결된 팀 RDS다. 운영·스테이징 웹사이트의 배포 상태까지 확인한 결과는 아니다. 기존 미커밋 임베딩 작업은 보존했다.

## API 현황

Swagger에는 GET/POST/PUT을 구분해 총 18개 작업이 등록돼 있다. 이번 HTTP 점검은 읽기 요청 11개이며 모두 예상 상태로 응답했다. 사용자 생성·프로젝트 등록·평가 저장은 이번에 실제 사용자 데이터에 실행하지 않았다.

|---|---|---|
| 상태 | `GET /api/health` | 200 |
| 공고 목록·상세 | `GET /api/postings`, `/{postingId}` | 200, 총 1,945건 |
| 역량 사전 | `GET /api/capabilities` | 200, 62개 |

카카오엔터프라이즈 공고 1721의 회사 자료 조회는 READY·2건이지만 모집 단위 3204의 비교 수집 상태는 NOT_REQUESTED·0건이다. 회사 전체 자료와 동일 표준 직무의 비교 자료를 별도로 집계하므로 회사 READY를 모든 모집 단위의 비교 준비 완료로 표시하면 안 된다.

비교 후보/수집 상태 조회는 이번 표본에서 약 23.3초/22.4초였다. 응답 성공과 별개로 사용성에 영향을 주는 지연이다. 요청별 DB 왕복과 전체 후보 특징 로딩 비용을 측정한 뒤 조회 일괄화·캐시 적용 여부를 정해야 한다. 이번 작업에서 원인 확정이나 성능 개선 완료로 보고하지 않는다.

## 실제 데이터와 이번 추가 수집

공고는 1,945건, 진행 중은 1,788건, 현재 추출이 있는 공고는 1,944건이다. 현재 추출 중복은 없고 1건은 현재 추출이 없다. 마지막 공고 수집은 11월 5일이며 11월 9일 신규 수집은 0건이다. 공고 수집 Daily와 합격자료 Daily는 서로 다른 작업이므로 공고 갱신 중단 여부를 별도로 확인해야 한다.

| 항목 | 시작 시 | 추가 수집 후 |
|---|---:|---:|
| 외부 합격자료 | 5건 / 3개 회사 | 7건 / 5개 회사 |
| 별도 본문 | 3건 | 5건 |

오늘 미시도 회사 중 3곳을 기존 한도(회사당 2페이지·40후보)로 확인했다.

- 라인플러스(1356): 검사 1건, 수락 1건.
- 토스페이먼츠(1091): 검색 후보 0건, 수락 0건.
- 쿠팡(1978): 검사 3건, 타사 1건·직무 제외 1건, 수락 1건.

수락한 2건은 본문·기술 요약·공고 연결과 함께 저장했다. 각각 회사 자료가 1건이므로 상태는 INSUFFICIENT다. 공개 합격자소서 자료의 추가 확보이며, 검증된 합격자 계정·역량 LV 표본이 늘었다는 의미는 아니다. 기존 본문 추출 대기 상태도 실제 역량 평가 완료와 구분한다.

실행 증거: `work/targeted-backfill-20261109.json`, 최종 RDS 집계와 공고 조인 내보내기: `work/current-rds-audit-20261109.json`, `work/posting-current-joined-20261109.csv`.

## 더 확보하기 위한 변경과 우선순위

1. **회사 검색 별칭**: 공개 검색에서 `엔에이치엔(주)`·`엔에이치엔`은 0건, `NHN`은 8건이었다. 검색 결과에는 계열사가 섞여 있다. [NHN 공식 사업보고서](https://www.nhn.com/ko_/ir/AuditReport/2024/%5B%EC%97%94%EC%97%90%EC%9D%B4%EC%B9%98%EC%97%94%5D%EC%82%AC%EC%97%85%EB%B3%B4%EA%B3%A0%EC%84%9C%2820240319%29.pdf)의 회사 명칭을 근거로 동일 법인임을 확인한 별칭만 사용해야 한다. 단일 회사 실행에 `--company-search-name`을 추가했다. 검색·상세의 정확 회사 일치를 모두 검사하며 계열사를 자동 허용하지 않는다. NHN은 이미 당일 시도했으므로 오늘 재수집하지 않았다. 이 8건을 확보 건수에 포함하지 않는다.
2. **회사 선별**: 오늘 정규 배치가 회사 ID 순으로 처리한 30곳에서는 0건이었지만 별도 선정한 3곳에서는 2건을 확보했다. 이 작은 표본만으로 수율을 일반화할 수는 없다. 자료가 확인된 회사·비교 후보 회사·누락 직무를 우선 처리하는 운영 순서를 검토할 근거는 된다. 기본 30곳/일이면 1,143개 대상 회사를 한 번 훑는 데만 최소 약 39일이 필요하다. 이번에 일일 한도는 올리지 않았다.
3. **제외 원인 집계**: 일일 결과에 `examined`, `foreign_company`, `excluded`를 추가했다. 검색어 문제·타사 제외·직무 판별 문제를 나눠 다음 변경을 결정할 수 있다. 일반 SW·복수 직무를 근거 없이 backend 등으로 승격하지 않는다.
4. **기존 본문 활용**: 본문은 저장돼 있지만 추출 대기 중이다. 근거 문장과 기술·프로젝트 신호를 먼저 추출하고 사람별 중복과 검증 상태를 정리해야 실제 합격자 역량 비교로 연결할 수 있다. 자소서 기술 언급을 LV로 바로 변환하지 않는다.
5. **추가 출처**: 출처별 공개 접근 가능 여부·회사/직무 메타데이터·중복 ID를 확인한 뒤 별도 Adapter로 추가해야 한다. 이번에 새 출처 연동이나 접근 제한 우회는 추가하지 않았다.
