# 카테고리 API·공고 프론트 연결 검증 (2026-11-19)

## 변경

- 임베딩 추가 호출 중단. 기존 검토 HTML의 7,595개 원문에 대한 해시·분류만 서버 리소스로 내보냈다. 벡터·원문 목록은 서버 리소스에 포함하지 않는다.
- 기술 10개·기타 관련 묶음·보조 태그·집계를 `GET /api/skill-categories`로 제공한다.
- 공고의 현재 필수·우대 문장을 `GET /api/postings/{postingId}/skill-categories`로 조회한다. 새 문장은 UNCLASSIFIED, 제외는 EXCLUDED, 업무·기타 항목은 NOT_APPLICABLE이다. OTHER는 분류 코드이므로 미분류와 별도다.
- 기존 capability ID, 추출 결과, LV 계산·점수는 변경하지 않았다. 프론트 차트와 카테고리별 LV UI는 이번 작업 범위 밖이다.
- Next.js에 카테고리 중계를 추가했다. `be:` 공고 상세는 최근 200개 목록 캐시에 의존하지 않고 해당 ID를 직접 조회하도록 수정했다.
- 프론트 API 계약 검사를 CI에 추가했다. 웹 배포는 환경별 데이터 폴더의 선택적 `.env`를 읽도록 했다.

## 검증 결과

- Java 21 백엔드 전체 테스트: 178개 중 성공 163개, 조건부 PostgreSQL 검사 15개 생략, 실패·오류 0. 새 카테고리 검사 4개 포함. PostgreSQL 검사까지 모두 실행했다고 보고하지 않는다.
- 백엔드 실행 JAR 빌드 성공.
- 프론트 API 계약 검사 5개 성공, 변경 파일 ESLint 성공, 프로덕션 빌드 성공. 최초 제한 환경에서의 Google Fonts 다운로드 실패는 네트워크 허용 환경 재실행에서 해소했다.
- 로컬 `career-db-snapshot`에 읽기 전용 JDBC로 임시 Spring을 연결했다. 임시 Next.js도 실행해 실제 HTTP 연결을 검사하고 두 서버를 종료했다. 기존 8080 서비스는 교체하지 않았다.
- 로컬 공고 목록: 1,717개. Swagger 작업 수: 20개.
- 공고 4374: CLASSIFIED 12, EXCLUDED 2, NOT_APPLICABLE 5. 공고 4373: CLASSIFIED 18, NOT_APPLICABLE 9. 필수·우대 표본의 UNCLASSIFIED는 0이었다. 전체 최신 DB의 모든 문장을 HTTP 전수 검사한 결과는 아니다.
- 임시 프론트에서 공고 4371~4375 상세 조회 성공, 카테고리 중계 결과는 Spring 집계와 동일했다.
- 실제 사용자·RDS 쓰기 요청, 유료 모델·임베딩 호출은 하지 않았다.

로컬 원시 검증 집계: `work/category-api-http-smoke-20261119.json`. 읽기 전용 검사 실패 시 로그에는 연결 설정이 포함될 수 있으므로 로그 전체를 저장소에 넣지 않는다.

## 스테이징 한계

변경 전 공개 스테이징 `/api/jobs?limit=24`는 200, 총 6개였으며 `be:` ID는 없었다. 백엔드 공고의 실제 스테이징 표시를 확인하지 못했다. 기존 CD가 배포하는 것은 웹이며 Spring 서비스는 별도다. 실제 스테이징 Spring 주소·서비스·DB 설정을 확보하기 전에는 연결 완료로 보고할 수 없다. 이번 작업에서 서버 주소·자격증명·DB를 추측하여 배포 설정을 채우지 않았다. `develop` 코드 반영과 스테이징 백엔드 배포는 구분한다.

API 표는 [전체 API 목록](../api-inventory-20261119.md), 분류 정의와 응답 계약은 [카테고리 API](../skill-category-api.md)를 참고한다.
